ENTRY 001

Date: 31 August 2026
Decision: Limit the assessed prototype to one complete Kitchen Memory Reconstruction Loop.
Reason: A narrow vertical slice demonstrates the core research argument more reliably than three incomplete domains.
Alternatives considered: Partial Kitchen, Garden, and Ritual spaces; a visually complete Kitchen without a real model interaction.
Effect on scope or research argument: Garden and Ritual are deferred. The prototype prioritises real AI output, visible model limitation, user evaluation, correction, and local preservation.

ENTRY 003

Date: 31 August 2026
Decision: Use the free Gemini Developer API as the primary live model provider, with Groq Cloud as a fallback, and require only a successful local demonstration.
Reason: Supervisor feedback recommends Google AI Studio because it is free, reliable, easy to configure, and supports an OpenAI-compatible interface. The assessment requires live AI output but does not require deployment.
Alternatives considered: Groq Cloud as the primary provider; deploying a serverless function before testing locally; using a paid API.
Effect on scope or research argument: The live AI requirement remains unchanged. Deployment is removed from the prototype definition of done, reducing technical risk without changing the core interaction or research argument.
Related commit: To be added after this document is committed.


ENTRY 004

Date: 31 August 2026
Decision: Build in small inspect, commit, and push increments, with styling after the complete static interaction loop and Gemini integration after styling.
Reason: This matches the project owner's preferred workflow and makes each change easy to monitor, verify, and reverse.
Alternatives considered: Designing the full visual system first; building several routes and features in one implementation phase; connecting the API before the interaction states exist.
Effect on scope or research argument: No change to the argument. The sequence reduces implementation risk and creates clearer process evidence for the Critical Reflection.
Related commit: To be added after this document is committed.


ENTRY 005

Date: 31 August 2026
Decision: Connect and test the live Gemini model before completing page-specific visual styling.
Reason: Live generative output is the assessed prototype requirement. Testing real response length, latency, errors, and tone before visual polish will allow the interface to be styled around actual model behavior rather than temporary sample content.
Alternatives considered: Complete all page styling before creating the local server and Gemini integration.
Effect on scope or research argument: The prototype scope does not change. The implementation order changes so functional and theoretical risk is addressed before visual polish.
