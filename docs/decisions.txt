ENTRY 001

Date: 31 August 2026
Decision: Limit the assessed prototype to one complete Kitchen Memory Reconstruction Loop.
Reason: A narrow vertical slice demonstrates the core research argument more reliably than three incomplete domains.
Alternatives considered: Partial Kitchen, Garden, and Ritual spaces; a visually complete Kitchen without a real model interaction.
Effect on scope or research argument: Garden and Ritual are deferred. The prototype prioritises real AI output, visible model limitation, user evaluation, correction, and local preservation.

ENTRY 003

Date: 31 August 2026
Decision: Use the free Gemini Developer API as the primary live model provider, with Groq Cloud as a fallback, and require only a successful local demonstration.
Reason: Supervisor feedback recommends Google AI Studio because it is free, reliable, easy to configure, and supports an OpenAI-compatible interface. The assessment requires live AI output but does not require deployment.
Alternatives considered: Groq Cloud as the primary provider; deploying a serverless function before testing locally; using a paid API.
Effect on scope or research argument: The live AI requirement remains unchanged. Deployment is removed from the prototype definition of done, reducing technical risk without changing the core interaction or research argument.

ENTRY 004

Date: 31 August 2026
Decision: Build in small inspect, commit, and push increments, with styling after the complete static interaction loop and Gemini integration after styling.
Reason: This matches the project owner's preferred workflow and makes each change easy to monitor, verify, and reverse.
Alternatives considered: Designing the full visual system first; building several routes and features in one implementation phase; connecting the API before the interaction states exist.
Effect on scope or research argument: No change to the argument. The sequence reduces implementation risk and creates clearer process evidence for the Critical Reflection.

ENTRY 005

Date: 31 August 2026
Decision: Connect and test the live Gemini model before completing page-specific visual styling.
Reason: Live generative output is the assessed prototype requirement. Testing real response length, latency, errors, and tone before visual polish will allow the interface to be styled around actual model behavior rather than temporary sample content.
Alternatives considered: Complete all page styling before creating the local server and Gemini integration.
Effect on scope or research argument: The prototype scope does not change. The implementation order changes so functional and theoretical risk is addressed before visual polish.
Related commit: To be added after this document is committed.


ENTRY 006

Date: 1 September 2026
Decision: Expand the one-shot reflection into a bounded conversational reconstruction with up to three follow-up answers and a user-triggered working recipe.
Reason: Live testing showed that the model's sensory question could prompt useful memory, but the interface did not allow the user to answer it. A bounded conversation better demonstrates cultural reconstruction as an active process while keeping the user, rather than the model, as the source of recipe knowledge.
Alternatives considered: Keep the one-shot loop unchanged; allow unlimited chatbot conversation; let the model provide regional recipes; add a single follow-up only.
Effect on scope or research argument: The Kitchen remains the only domain, but its core interaction becomes deeper. The model may organise user fragments but may not fill missing recipe details. Unlimited chat and AI-authored regional recipes remain outside scope because they would increase model drift and reposition the AI as a cultural authority.
Related commit: To be added after this document is committed.


ENTRY 007

Date: 2 September 2026
Decision: Prioritise practical reconstruction questions over broad sensory or atmospheric questions.
Reason: Live output showed that a question about surrounding sounds or smells could be cautious without helping the user recover a usable family method. Questions should first target counts, preparation, sequence, heat, texture, readiness, substitutions, or family terms. Sensory recall remains useful when it identifies a cooking decision.
Alternatives considered: Keep the original sensory-first prompt; allow Gemini to supply generic quantities and timings; turn the experience into a regional recipe assistant.
Effect on scope or research argument: The AI becomes more useful as an interviewer without becoming the source of family knowledge. Generic cooking guidance remains outside the remembered recipe unless a later, separately labelled and sourced comparison feature is deliberately added.
Related commit: To be added after this document is committed.


ENTRY 008

Date: 2 September 2026
Decision: Use Gemini as the primary provider with Groq as an automatic temporary-failure fallback.
Reason: Gemini free-quota failures repeatedly prevented live testing of the assessed interaction. Provider resilience is required for a reliable demonstration.
Alternatives considered: Wait for the Gemini quota to reset; replace Gemini entirely; use hard-coded fallback output.
Effect on scope or research argument: The live-output requirement remains intact. Both providers use the same prompts and local validation, and the privacy notice explains that either configured service may receive demonstration text.
Related commit: To be added after this document is committed.


ENTRY 009

Date: 2 September 2026
Decision: Preserve complete bounded conversations in a version 2 browser archive while continuing to read version 1 entries.
Reason: Saving only the latest reflection removed the user-led reconstruction process that the revised concept is intended to demonstrate.
Alternatives considered: Delete version 1 data; save only the Working Family Recipe; leave archive persistence unchanged.
Effect on scope or research argument: The Living Archive now preserves authorship, model uncertainty, user evidence, visible unknowns, and the final user decision without claiming to archive culture itself.
